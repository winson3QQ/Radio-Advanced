開場的三句話

  • LoRa、LoRaWAN、Meshtastic 是三個層次的東西，卻經常被當成同義詞。這一節結束後，學員必須能一句話說清楚三者的差別。

第一部 · TCP/IP 四層，以及為什麼第一層要再拆

TCP/IP 四層模型是網路教學的標準框架。但直接拿來分析無線科技會失去解析度——因為那九個名詞裡有六個全部擠在第一層裡面。

先講一件會造成誤讀的事 · 層編號

本文件的 L1–L4 是 TCP/IP 四層模型的編號，與 OSI 七層模型的 L1–L4 完全不同。做網路的人看到「L2」幾乎都會反射性想到 OSI 的資料鏈結層，但在這份文件裡：

本文件（TCP/IP 四層）對應到 OSI 七層
L4 應用層OSI L5–L7
L3 傳輸層OSI L4
L2 網際網路層（IP）OSI L3 網路層
L1 網路存取層OSI L1 ＋ L2

最容易出事的是本文件的 L2 是 IP 層，不是 OSI 的資料鏈結層。授課時建議直接講名稱（「網際網路層」「網路存取層」），不要只講編號。

為什麼 L1 必須再拆成三個子層

中繼台就是 1c 層的類比實作。學員在第一節已經懂了「訊號要經過一個轉發者、而且轉發者收發用不同頻率」。第二節只要說一句「網狀網路就是每個人都同時是中繼台」，整個概念就接上了——差別只在於中繼台是人工規劃的，網狀網路是自動決定的。

第二部 · 網路拓樸 · 四種形狀

拓樸決定的是「誰能跟誰講話」，以及「誰壞掉的時候會發生什麼事」。這是民防最該關心的一層，因為它直接對應到韌性。

紅色節點＝失去它整個網路就斷。網狀拓樸沒有紅色節點，這就是它的全部價值。

拓樸特性單點失效代價民防對應
點對點兩台直接連無只能兩個人簡易通信（Simplex）
星狀全部連到中心中心倒＝全倒中心是瓶頸也是靶中繼台、LoRaWAN、4G 基地台
樹狀星狀的多層版上層倒＝下層全倒失效會擴散階層式指揮體系
網狀每個節點都能轉發無頻寬被轉發吃掉Meshtastic、802.11s
網狀不是免費的

網狀拓樸換來韌性，付出的代價是空中時間。同一則訊息要被轉發很多次，每一次轉發都佔用一次頻譜。所以網狀網路的有效頻寬會隨節點數與跳數快速下降——這是物理限制，換晶片、換韌體都不會消失。

這也解釋了為什麼「網狀 + 低頻寬實體層」的組合（例如 Meshtastic）只能傳極短的訊息，而「網狀 + 高頻寬實體層」的組合（例如 802.11s）覆蓋距離又很短。你不可能同時要韌性、頻寬和距離。

先解決一個命名陷阱：MANET 就是 Mobile Ad-hoc NETwork

MANET 的全名是 Mobile Ad-hoc NETwork，名字裡本來就有 Ad-hoc。所以「MANET 支不支援 ad-hoc」聽起來像廢話——但它其實不是廢話，因為 Ad-hoc 這個詞有兩個完全不同的意思：

Ad-hoc 的哪個意思指的是MANET 名字裡是哪一個
架構概念無基礎設施、臨時組成、沒有事先規劃✔ 就是這個
802.11 的 IBSS 模式一個具體的 MAC 運作模式，節點不透過基地台直接交換訊框✘ 不是這個
這個區分能解開什麼

MANET 的名字裡有 ad-hoc，不代表它必須用 802.11 的 IBSS 模式實作。一個 MANET 可以：

  • 用 IBSS 實作——傳統做法，現在較少用
  • 用 802.11s mesh point 實作——OpenMANET 走的就是這條路
  • 用專有波形實作——商用戰術電台
  • 完全不用 802.11——Meshtastic 自訂封包格式

所以當你問「底層沒支援 ad-hoc 怎麼辦」時，正確的問法是：這個晶片的 MAC 有沒有提供任何一種讓兩個節點直接交換訊框的模式？IBSS 只是其中一種答案，802.11s mesh point 是另一種——而且在 HaLow 上是比較可靠的那一種。

Ad-Hoc、Mesh、MANET 三個詞的關係

釐清命名之後，三個詞回答的是不同問題：

名詞回答的問題在 802.11 裡的具體實作層
MANET「拓樸一直在變，還能不能通？」
——自動找路、容忍移動		batman-adv、Babel、OLSRL2 / 1c
Mesh「訊號有幾條路可以走？」
——每個節點都能替別人轉發		802.11s MBSS（多跳，含轉發）1c
Ad-Hoc「有沒有基地台？」
——沒有，節點直接互通		IBSS 模式（單跳，不做轉發）1b

包含關係是：Ad-Hoc ⊃ MANET（MANET 是「會移動的」ad-hoc 網路）。而 Mesh 是形狀，跟前兩者是不同軸的描述。

最關鍵的差別 · IBSS 不做轉發

Ad-Hoc（IBSS）只提供「鄰居之間能直接交換訊框」，它本身不做多跳轉發。兩個聽不到彼此的節點，即使都在同一個 IBSS 裡，也無法互通。

要跨越多跳，必須另外有人做轉發——那是 802.11s 或 MANET 路由協定的工作。這兩件事缺一不可，而且不能互相取代。

Mesh 與 MANET 的差別

這兩個詞在民防圈幾乎被當成同義詞，但它們描述的是不同的東西：

名詞描述的是關鍵問題
Mesh形狀：每個節點都能替別人轉發「訊號有幾條路可以走？」
MANET能力：自己找路、節點會移動、沒有預先規劃「拓樸一直在變的時候，還能不能通？」

所有 MANET 都是 mesh，但不是所有 mesh 都是 MANET。架在屋頂上位置固定的 802.11s 網路是 mesh，但不是 MANET——因為拓樸幾乎不變。背在身上邊走邊用的節點才需要 MANET 的能力。

MANET 的核心難題

拓樸變得比路由表更新得還快。傳統路由協定要靠控制封包或附加中繼資料來維護路徑，而每一次維護都吃掉空中時間。當節點頻繁移動時，維護路由的開銷會超過它帶來的好處 FACT。

這正是 Meshtastic 選擇洪泛而不是路由的原因——在低頻寬、高移動性的環境下，「大家一起轉發」反而比「算出最佳路徑」更划算。這是工程取捨，不是技術落後。

同一個詞指兩件事，是討論時最常見的雞同鴨講。有人說「我們要用 MANET」時，可能是指「在現有 Wi-Fi 上跑 Babel」，也可能是指「買一台十萬元起跳的戰術電台」。務必先問清楚。

觀念釐清

Meshtastic 不是一個 IP 網路。它有自己的封包格式與定址方式，不跑 IP、不跑 TCP/UDP。

這件事的真正代價不是「什麼都不能跑」，而是每一個應用都要單獨施工：IP 網路上任何應用插上去就能用，非 IP 網路上每個應用都需要一個專屬的適配器。第五部會用 TAK 當例子詳細說明。

課堂提問 · 下層沒有 ad-hoc，上層有 MANET，能通嗎？

這是分層框架最好的一道考題。答案是：能通，但你得到的不是 MANET。

核心原則

路由協定只能決定「走哪一條路」，不能創造「本來不存在的路」。

MANET 路由協定（batman-adv、Babel、OLSR）有一個前提假設：如果 A 和 B 在無線電涵蓋範圍內，A 就能直接送一個訊框給 B。它在這個假設上建立鄰居表、算路徑。

如果底層 MAC 只提供基地台對用戶端，那麼兩個用戶端之間在連結層根本沒有直接的路——即使它們的天線相距三公尺。

硬跑會發生什麼
#結果為什麼
1路由協定忠實地發現一個星狀拓樸它沒有壞掉，它只是照實回報它看到的東西——而它看到的就是星狀
2每一「跳」實際上是兩次無線傳輸用戶端 → 基地台 → 用戶端。吞吐減半、延遲加倍、佔用的空中時間加倍
3基地台一倒，底下所有節點全部孤立路由協定無路可繞，因為連結層沒有替代路徑可供選擇

第三點是關鍵：你採用 MANET 就是為了避免單點失效，而這個組合把單點失效原封不動地保留下來了。

用第一節的東西類比

兩台手持機如果彼此聽不到、只能透過中繼台通聯，那麼無論你在上層做多聰明的規劃，都不會讓它們變得能直接通聯。可達性是實體層與連結層的事實，上層只能在既有的可達性上做選擇。

這跟第一節反覆強調的「軟體不能修好天線」是同一件事，只是搬到了網路層。

HaLow 的實際狀況 · 查證結果
好消息

HaLow 晶片實際上有支援 802.11s mesh point 模式 FACT。Alfa Network 表示其 NRC7292 產品支援 IEEE 802.11s；Gateworks 的文件指出 Morse Micro 提供修改版的 hostapd 與 wpa_supplicant 支援 802.11ah，且大多數使用情境（含 AP、STA、802.11s Mesh）不需額外核心修補，其 GW16146 文件同時列出 802.11s Mesh 與 Adhoc/IBSS 兩種設定範例。

但 IBSS 被當成 legacy 且不穩定

Gateworks 明確把 IBSS 稱為「舊的」模式，並註明某個核心修補只有 IBSS 搭配 bridge 時才需要、802.11s Mesh 不需要 FACT。Morse Micro 社群近期也有回報：同一份 OpenWRT 映像下 802.11s 運作正常，切到 ad-hoc/IBSS 卻出現核心崩潰 FACT。

主流架構

802.11s 提供鄰居可達性，batman-adv 或 Babel 在上面做路由。OpenMANET 就是這個架構——基於 Raspberry Pi 與 Morse Micro HaLow 板，跑 OpenWrt，802.11s 加 batman-adv，對終端呈現一個扁平的區域網路，即使背後可能跨越多個 HaLow 跳點 FACT。

評估時的判斷口訣

不要問廠商「支不支援 mesh」，要問「兩個用戶端之間能不能直接交換訊框」。

因為「支援 mesh」在行銷文件裡可能指的是：每個節點同時開一個基地台和一個用戶端，串成一棵樹。那是樹狀不是網狀——根節點倒了整棵斷，跟你要的韌性完全無關。

第三部 · 九個名詞的層位定位

點下面任何一個名詞，看它自己提供哪幾層、以及依賴別人提供哪幾層。這個區分是整節課的核心。

選擇上方任一項目目前顯示完整的層次架構。點選任一名詞後，綠色代表它自己提供的層，琥珀色代表它必須依賴其他技術提供的層，紫色代表它承載或整合了所有層但自己不是任何一層。
操作完之後要學員說出的結論
  • 只有 4G/5G 一個人包辦全部層次。這既是它最方便的地方，也是它最脆弱的地方——因為那些層次全部由第三方擁有。
  • TAK 什麼層都不提供，只有 L4。它是最容易被誤會成「一種通訊技術」的東西，實際上它完全不管底下怎麼傳。
  • 802.11ah 自己不提供 1c 層。它的網路架構以基地台為中心（RAW、TWT、階層式 AID 都以基地台排程為前提），標準沒有為 sub-1 GHz 定義專屬的網狀機制 FACT。網狀要靠 802.11s——它屬於基礎 802.11 標準，但實際能不能用取決於晶片韌體有沒有開放 mesh point 模式。

OpenWrt · 為什麼它決定你能不能拿到 mesh

OpenWrt 本身不在四層框架裡——它是讓那些層跑起來的執行環境。但在 HaLow 的世界裡它有一個特殊地位：

廠商的 802.11ah 驅動與工具幾乎都以 OpenWrt 為第一支援平台。Morse Micro 提供的是修改版的 hostapd_s1g 與 wpa_supplicant_s1g，加上 morse_cli 這個廠商專用工具，因為許多 802.11ah 的設定選項無法透過標準的 nl80211 介面傳遞，只能用廠商專屬指令 FACT。

實務上的意義：「用不用 OpenWrt」不是偏好問題，而是決定你拿不拿得到 802.11s。如果你堅持用一般的 Debian 或 Raspberry Pi OS，往往要自己回頭移植這些補丁與工具。

OpenMANET · 整合方案在做什麼

OpenMANET 是一個基於 Raspberry Pi 的 MANET 電台專案，建構在 Wi-Fi HaLow 之上，圍繞 Morse Micro 的 HAT 與 SDIO 板設計，跑 OpenWrt，支援 802.11s 加 batman-adv，並包含 GPSD 驅動的距離測試與 PTT 應用 FACT。

它對終端使用者呈現一個扁平的區域網路，即使 BATMAN-V 在背後可能跨越多個 HaLow 跳點傳送訊框 FACT。這正是前一節「802.11s 提供可達性、batman-adv 提供路由」的具體實作。

它的價值不在發明，在選型與調校。每一層都是現成的元件，但要讓它們一起正常運作、參數調對、預設值合理，是相當可觀的工程量。

OpenMANET 的供應鏈風險

OpenMANET 專案文件提到目前特別針對 Seeed HaLow 板建構，並列出 Heltec HT-HD01V2 等硬體選項 FACT。這兩者皆為中國廠商 供應鏈。

這是「軟體乾淨、硬體不乾淨」的又一個實例——與 Meshtastic 的情況完全相同。專案本身是開源可審查的，但參考硬體落在需要排除的供應鏈上。

較乾淨的替代路徑：Morse Micro HaLowLink 2（澳洲）、Alfa Network 的 HaLow HAT（台灣）、Gateworks 的板卡（美國）。三者都能跑 OpenWrt 加 802.11s，但整合工作量會比直接用 OpenMANET 的參考硬體高 推論。

用無線電當底層 · 封包無線電教學對照組

這是第二節與第一節接得最緊的一段：學員手上那台已經練習過十一個實驗的手持機，本身就是一個可用的資料實體層。

這一段的定位

封包無線電在 2026 年的實際部署價值有限——1200 bps 與 Meshtastic 同一個量級，而且不能加密。把它放進課程的理由是教學，不是推薦部署：

  • 它是唯一一個學員手上已經擁有的資料鏈路，不需要買任何新設備
  • APRS 對 TAK 的並列，是四層框架最好的示範——同一層、不同底層、隔了三十年
  • 業餘頻段禁止加密這條法規，透過它來講最自然
它為什麼存在
要解決的問題

1980 年代業餘無線電社群想傳資料，但沒有任何無線資料網路可用。手上唯一的東西是為語音設計的 FM 電台。

設計原理

既然電台能傳語音，就把資料編碼成音訊再送進麥克風孔。接收端把喇叭輸出解回資料。中間那個轉換裝置叫做數據機（TNC，Terminal Node Controller）。

連結層協定 AX.25 借用自 X.25，最大的特色是用呼號當位址——這在當時是很自然的選擇，因為法規本來就要求你必須表明身分。

兩種速率
  • 1200 bps AFSK：資料變成兩個音頻音調，走一般麥克風與喇叭接口。任何一台 FM 電台都能用，不需改機
  • 9600 bps FSK：直接調變到鑑頻器，需要電台有專用的數據接口。速率快八倍，但機種限制多

最關鍵的一條法規限制

國際電信聯盟無線電規則 RR 25.2A 規定：不同國家之間的業餘電台通信，不得為了隱藏意義而編碼（業餘衛星服務的控制訊號除外）FACT。

這裡要講精確

這條 ITU 條文只約束「跨國」通信，不是一條全球通則。國內通信的規範由各國自行訂定，而且各國作法不同：美國 FCC 把禁令擴及國內通信；加拿大則允許使用加密，但金鑰必須公開發布。

台灣的具體條文請以最新法令為準 待查——這是開課前必須查清楚的項目，不能用「業餘就是不能加密」帶過。

另外要注意條文的關鍵字是「為了隱藏意義」。莫斯電碼、Baudot、ASCII、FT8、數位語音都是「編碼」，但目的不是隱藏意義，所以不在禁止之列。判斷標準是意圖，不是有沒有用到編碼。

這代表任何跑在業餘頻段上的資料——APRS 位置、Winlink 郵件、AREDN 上的 TAK——全部都是明文，任何人都能完整接收與解讀。

這一點直接呼應第一節的「亞音不是加密」。同一個教訓在兩節課出現兩次，只是規模不同：第一節是你以為亞音保護了你，第二節是整個頻段在法律上就禁止你被保護。需要保密的內容，不能走這條路。

當下層不夠時 · 應用層適配

「用 Meshtastic 跑 TAK」這件事實際上做得到，而且有官方支援。但它的做法不是你想的那樣，而這個差別正是分層框架最有價值的地方。

兩條路，不是一條

當下層的承載能力不足以支撐上層應用時，工程上有兩條路：

  1. 換掉下層——改用頻寬夠的實體層，例如 802.11ah 加 802.11s
  2. 在應用層做適配——接受下層的限制，把資料重新設計成能通過那條管道的形狀

Meshtastic ATAK Plugin 走的是第二條。它沒有假裝 Meshtastic 是 IP 網路，而是誠實承認頻寬限制，然後在應用層動手。

本部的核心結論

免執照頻段的功率上限是法規訂死的，人人都一樣。所以在這些技術上，功率不是可以競爭的變數。真正能改善的只剩下三件事：

  1. 天線——第一節實驗 10 已經證明它的效益遠大於功率
  2. 高度與視距——第一節實驗 10-5，零成本
  3. 降低資料率換取靈敏度——這是 LoRa 展頻因子的本質：傳得慢＝傳得遠

第三項是第二節新增的觀念，第一節沒有對應。它是所有低功率廣域技術的共同設計哲學：用時間換距離。

但有一個例外值得注意：走業餘頻段的方案（AX.25、APRS、AREDN）功率上限高得多，而且可以透過既有中繼台延伸涵蓋。這是它相對於免執照頻段方案最實質的優勢——代價是需要執照，而且不能加密。

佔空比：另一個被忽略的法規限制

920–925 MHz 這類頻段除了功率上限，通常還有佔空比（duty cycle）限制 待查。意思是你在一小時內只能發射總時間的一小部分。

這對網狀網路是雙重打擊：訊息本來就要被轉發很多次，而每個節點各自受佔空比約束。節點數越多，每個人能講話的時間越少。這是規劃 Meshtastic 網路時最容易被低估的天花板。

給學員的結論

沒有一種技術能同時滿足所有需求，所以正確的問題不是「該選哪一個」，而是「哪幾個要一起用、各自負責什麼」。

一個合理的民防通訊架構通常長這樣：語音用業餘無線電（第一節的內容）、位置與狀態用 Meshtastic 或 APRS、態勢圖與資料用 802.11ah 或 802.11s、4G/5G 當作平時的便利管道但不列入災時依賴。各自覆蓋不同的層次與場景。

而且要注意這個架構裡沒有任何一條路徑是保密的。業餘頻段法規禁止加密；免執照頻段雖可加密，但硬體供應鏈存疑。需要保密的內容必須另外規劃管道——這是規劃時最容易被跳過、卻最不能跳過的一步 推論。

本部的核心觀念 · 開源 ≠ 供應鏈安全

Meshtastic 是最好的教材：它的軟體是開源的、可以逐行審查，但硬體幾乎全部來自中國供應鏈。

這個「軟體乾淨、硬體不乾淨」的組合，正好訓練學員把兩件事分開看：

  • 可審查性：程式碼能不能被檢視？
  • 供應鏈信任：晶片、韌體、製造流程掌握在誰手上？

兩者互不保證。開源專案可以跑在不可信的硬體上，閉源產品也可以來自可信的供應鏈。選型時必須分開評估。

第九部 · 16 個觀念釐清

這一節的驗收標準：學員要能用一句話回答下面每一題。

常見說法為什麼不對
「802.11ah 和 HaLow 哪個好？」同一個東西。一個是 IEEE 標準編號，一個是 Wi-Fi Alliance 商標名 FACT
「我們要不要用 mesh？」Mesh 是拓樸不是技術。要先問「在哪一層做 mesh」「用什麼實體層」
「LoRaWAN 是 mesh 網路」它是星狀。所有節點都要連到閘道器，閘道器倒了就全倒
「用 Meshtastic 跑 TAK」做得到，但要問清楚是哪一種。它不是網路承載，是應用層適配——官方 ATAK Plugin 把 CoT 剝除顯示用資料、轉 protobuf、zstd 壓縮後送出。你得到的是位置與聊天的子集，不是完整 TAK
「Meshtastic 跑不了 TAK」也不對。二分法本身就是錯的問法。正確的問法是「跑得起來的是完整功能，還是經過適配的子集？」
「802.11ah 自帶 mesh」它自己不提供。網路架構以基地台為中心，網狀要靠 802.11s，而且實際能不能用取決於晶片韌體——同一個標準，不同晶片答案可能不同
「Meshtastic 是開源的所以安全」軟體開源不等於硬體可信。主流硬體幾乎全是中國供應鏈
「MANET 裡就有 ad-hoc，所以底層一定要開 ad-hoc 模式」不一定。MANET 名字裡的 ad-hoc 指的是架構概念（無基礎設施），不是 802.11 的 IBSS 模式。用 802.11s mesh point 實作也是 MANET
「OpenMANET 是一種新的無線協定」它不發明任何一層，是把 HaLow、OpenWrt、802.11s、batman-adv 組起來的整合方案
「Ad-Hoc 就是 mesh」Ad-Hoc 只做單跳。IBSS 讓鄰居能直接互通，但不做轉發；多跳要靠 802.11s 或 MANET 路由協定
「下層沒 ad-hoc，上層跑 MANET 就好」不行。路由協定只能選路，不能創造連結層不存在的路。結果會是「星狀網路上跑了一套 MANET 路由」，單點失效原封不動
「這個產品支援 mesh」要追問是哪一種。可能只是每個節點同時開 AP 加 STA 串成樹——根節點倒了整棵斷
「Mesh 和 MANET 是同一件事」Mesh 講形狀，MANET 講能力。所有 MANET 都是 mesh，但固定不動的 mesh 不是 MANET
「我們要用 MANET」先問是哪一種。是在現有設備上跑 Babel，還是買一台十萬元起跳的戰術電台？同一個詞兩種意思
「無線電只能傳語音」接上數據機就能傳資料。AX.25 已經運作四十年，APRS 就是 1980 年代的 TAK
「用業餘無線電傳加密的災情」幾乎可以確定不行，但要查清楚依據。ITU RR 25.2A 只約束跨國通信 FACT；國內規範各國自訂，台灣條文 待查。務實上應假設走這條路的資料全部是明文
兩節課的總結
第一節教的是

怎麼看懂一條無線鏈路：頻率、頻寬、功率、天線、以及怎麼判斷你聽到的東西是真是假。全部集中在 1a 實體層。

第二節教的是

怎麼看懂一個無線系統：那條鏈路上面還疊了哪些層、拓樸長什麼樣、誰掌握著哪一層。

兩節共同的方法

先問「這是什麼層次的東西」，再問「它好不好」。第一節用瀑布圖把物理現象攤開來看，第二節用分層框架把系統結構攤開來看——都是拒絕在資訊不對等的情況下比較。
